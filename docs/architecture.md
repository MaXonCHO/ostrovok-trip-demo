# Архитектура и решения

Сверка: разделы 18-26 ТЗ и прочитанная техничка. Продуктовая последовательность не меняется техническими решениями.

## Слои

| Слой | Вход / выход | Ответственность |
| --- | --- | --- |
| UI, src/features | TripView, команды | Композиция, жесты и доступные действия |
| Application | Валидированные команды и сессия | Членство, контекст, версии, use cases |
| Domain | Trip, Vote, Proposal | Единогласие, история, семантика отсутствия голоса |
| CatalogRepository | hotelId / cityId | Каталог, категории номеров и evidence |
| TripRepository | id, expectedVersion, command | Конкурентная запись и хранение поездки |
| AgentProvider | Trip, личная реплика | Текст ответа и предложения обновления контекста |
| RecommendationProvider | Подтверждённый контекст, сценарии | Набор сценариев и стабильная колода |
| GeoProvider | Отель, место, характеристика | Схема/маршрут и географическое evidence |

Реальные поставщики подключаются в src/data/providers.ts. UI не выбирает провайдер и не видит серверные ключи. Ошибка конфигурации явная. Все внешние входы API валидируются Zod до применения; ответ будущего поставщика должен валидироваться его адаптером.

## Состояния

Сценарий и отель разные entityType. Голоса `unseen`, `liked`, `rejected`. Пропуск остаётся unseen; отказ не удаляет интерес к сценарию. Каждый рассматривает все три сценария и отдельно подтверждает набор. Только liked всех активных участников попадает в пересечение. Ожидаемое приглашение учитывается: один организатор в поездке на двоих не создаёт ложного единогласия.

Одно veto исключает отель, но его можно явно пересмотреть или отменить голос. Нельзя автоматически повторять отклонённые карточки. Сценарный фильтр не создаёт отдельного голоса. Колода формируется один раз на selectionRevision, сохраняет общие hotelId, категории и цены. Веса ранжирования не подменяют голосование.

После всех лайков остаётся предложение конкретного hotelId, roomTypeId, цены и selectionRevision. Каждый отдельно подтверждает это предложение. Новый proposal сбрасывает подтверждения. При несоответствии актуальной цены/номера финальные подтверждения сбрасываются. Сохранённый выбор изменяется только после явного переоткрытия организатором.

Город, даты, бюджет, номера, состав и изменения пожеланий при готовых сценариях создают новую версию с историей. Мягкие предпочтения тоже пересобирают сценарии, чтобы пояснение не оставалось устаревшим. После сохранения новый участник сначала viewer. Переоткрытие явно включает его в новый выбор. Удаление/выход участника отражается в истории, не служит автоматическим компромиссом.

## Подбор

Поддерживаемые интересы нормализуются через отдельный словарь, каждому пожеланию сохранён автор и исходное сообщение. Бюджет имеет basis. При `stay` сравнивается цена номера × ночи × номера. Вместимость категории × число номеров должна вмещать ожидаемых участников.

Обязательные условия исключают нарушения. Неизвестная цена или обязательная тишина без данных допускают просмотр, но требуют уточнения и не становятся общим подтверждённым совпадением. Мягкая оценка суммы весов интересов на участника; сортировка сначала по минимальной индивидуальной оценке, затем сумме, затем цене и ID. Причины визуальных отказов дают штраф этому отелю в следующей версии подбора, интерес к сценарию сохраняется. Это демонстрационная формула, без научной валидации и фиктивных процентов.

## Хранение

JSON-файлы вне public. `trip-UUID.json`, `sessions.json`, `invites.json`, `host-questions.json`, `evidence.json`. Непредсказуемая session cookie содержит секретный токен; сервер хранит SHA-256 токена. Trip participants содержат userId, но не cookie. Ссылка приглашает вступить, после вступления голосовать можно только от своей сессии. Демо-персона разрешена только владельцу изолированной сцены.

Изменения сериализуются по ID, версия проверяется внутри очереди. Запись: новый временный файл, затем rename. Ошибки не сохраняют частичные изменения. Idempotency commandId хранит последние 200 команд поездки. Гарантия относится к одному Node-процессу; межпроцессных locks нет. Cookie и JSON должны сохраняться для продолжения поездки. В Docker данные в volume, процесс UID 1001.

## Отельер

Вопрос хранится отдельно. Свободный ответ разбирается по поддерживаемым определениям характеристик. Сначала предложение значения и области, затем явное подтверждение. Старые evidence не удаляются. Новая запись содержит источник, дату, synthetic и conflictsWith. Ответ о комнате не превращается в свойство всего отеля. Демо-кабинет ограничен вопросами текущей сессии.

## Ограничения

Ограниченный mock-диалог, подготовленная геометрия, иллюстративный медиакаталог и отсутствие промышленного аккаунта. Никакого настоящего поиска в картах. Видео нет, это явно показано. Материалы только ссылки/заметки. Голосовые расшифрованы как исходные требования, а не встроенная функция распознавания. Тематические отзывы синтетические. Накопленные сценарии представлены редакционными заготовками, не обучением на реальных путешественниках.
