Правила по технике

Общие правила


Код на GitHub: только в одном репозитории, который был создан для вашей команды, в организации https://github.com/orgs/ostrovok-hackathon-2026/.



Обязательные файлы: README.md, docker-compose.yml, Dockerfile (один или несколько, если сервисов несколько), .env.example.



Тег сдачи: в дедлайн поставьте git-тег submission на последнем коммите основной ветки.



Запрещено: приватные зависимости/реестры без публичного доступа жюри.



Развертывание решения: ваш проект должен запускаться и корректно работать локально.



Демо-видео: обязательно нужно записать видео-скринкаст с обзором приложения. Видео можно залить на любой общедоступный хостинг (Яндекс.Диск, Google Drive, и т.д.), убедитесь, что видео доступно для просмотра в режиме инкогнито.




В случае, если возникнут проблемы при локальной развёртке — мы не сможем убедиться в корректности вашего решения, проставить соответствующие баллы и оценить его.



README.md


Краткое описание: что делает решение.



Быстрый старт: команды для запуска, от git clone до localhost:8080.



Зависимости и переменные окружения: требования по ресурсам, перечисление зависимостей (БД, кэш и т.д.), перечисление переменных окружения со значениями по умолчанию (не отменяет наличие .env.example



Данные/сидирование: как загрузить/создать демо-данные.



Структура API/UI: что на 8080, базовые маршруты (/, /health), тестовые учетные данные.



Если нет веб-интерфейса: точные шаги запуска и примеры ожидаемого вывода/результатов.

# Название проекта (трек)

Одно-два предложения, что делает решение.

- ссылка на видео-скринкаст (обязательно)
- ссылка на развёрнутый сервис (опционально)

## Быстрый старт

```bash
git clone <URL репозитория>
cd <repo>
cp .env.example .env   # если нужно
docker compose up --build
# открыть http://localhost:8080
```

## Зависимости и переменные окружения

Рекомендованные ресурсы:
- X CPU cores
- YGB RAM

- Postgres 16 (в `docker-compose.yml` как `db`)
- Redis (опционально)

- `APP_PORT` (по умолчанию `8080`)
- `DB_URL` (пример: `postgres://app:app@db:5432/app`)

## Сидирование

```bash
# пример: создаем таблицы/данные
docker compose exec app bash -lc "python manage.py migrate && python manage.py loaddata seed.json"
```

## Маршруты/доступ

- `/` — UI
- `/health` — 200 OK, JSON `{ "status": "ok" }`
- Тестовый пользователь: `admin / admin123` (если релевантно)

## Если нет веб-интерфейса

Точные команды запуска, формат входных данных, пример вызова и пример вывода.

Docker


Контейнер(ы) обязательны: приложение и все зависимые сервисы в Docker.



Порт: приложение внутри контейнера слушает 8080; в Compose проброс 8080:8080.



Multi-stage build: образ должен быть легким, без dev-инструментов в рантайме.



Без root: запускайте процесс под непривилегированным пользователем.



Секреты: в .env/docker secrets/env_file, без коммита реальных секретов.



Healthcheck: реализуйте /health в приложении и healthcheck в Compose.



Кроссплатформенность: укажите platform: linux/amd64 если собираете на Apple Silicon.


Docker Compose


Команда запуска: docker compose up --build (без дополнительных аргументов).



Файл: docker-compose.yml в корне репозитория.



Порты: пробросите 8080:8080 для сервиса приложения.



env_file: используйте .env/.env.example для конфигурации.



depends_on + healthcheck: корректный порядок старта и проверка готовности.


Запуск проекта


git clone, cd <repo>, cp .env.example .env (если нужно), docker compose up --build



Открыть http://localhost:8080 → видно решение.



Ограничение по времени: развертывание должно укладываться в разумное время на современном ноутбуке (ориентир ≤10 минут).



Без ручных доустановок: кроме Docker/Compose и копирования .env ничего выполнять не нужно.



Если решение без UI: все команды подробно описаны в README.md, включая путь к входным данным, формат ввода, примеры вызовов и ожидаемый результат.


Кросс-платформенность


Версионирование: фиксируйте версии базовых образов/зависимостей (не latest без крайней необходимости).



Логи: приложение пишет в stdout/stderr; при docker compose logs app видно причины отказа.



Сидирование/миграции: автоматизируйте на старте контейнера или опишите 1–2 команды в README.



Большие артефакты/модели: не хранить в гите. Используйте OpenAI-совместимое API.



Кросс-ОС: не полагайтесь на bash-специфику в рантайме контейнера, используйте POSIX-совместимые команды.


Рекомендуется (необязательно, но поможет и вам и нам)


Makefile с командами make up, make down, make seed.



Compose override для локального запуска: docker-compose.override.yml (логирование, маппинг кода).



CI: базовая проверка docker build и линтер.



Ссылка на развёрнутый сервис на каком-либо внешнем хостинге.
