# Островок! Моя поездка

Прототип трека «О!дин шаг до идеального отеля». Человек описывает желаемый отдых, выбирает сценарии, затем отели. У спутников отдельные сессии и личные диалоги. Общий результат требует единогласия и отдельного подтверждения выбранного номера.

Состояние: рабочий локальный прототип на демонстрационных данных. Бронирование и оплата отсутствуют. DeepSeek подключён для личного диалога и извлечения пожеланий. Реальный геосервис и автономное исследование источников пока не подключены.

Скринкаст: **ещё не опубликован**. Перед финальной сдачей добавить общедоступную ссылку и проверить в инкогнито. Репозиторий организации и тег `submission` пользователь подключает отдельно.

## Быстрый старт по техничке

```sh
git clone https://github.com/bershteinartem/ostrovok-trip.git
cd ostrovok-trip
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8080. Готовые сцены: http://localhost:8080/demo. Проверка: http://localhost:8080/health.

Публичный репозиторий прототипа: https://github.com/bershteinartem/ostrovok-trip. Перед сдачей в репозитории организации команды применяются её правила и тег `submission`.

Dockerfile имеет несколько стадий; runtime использует standalone-сборку, непривилегированного пользователя UID 1001, фиксированный Node и порт 8080. Compose задаёт `platform: linux/amd64`, healthcheck и volume `trip-data`. Других сервисов нет, поэтому `depends_on` не нужен. Логи: `docker compose logs -f app`. `docker compose down` сохраняет поездки; `down -v` уничтожает volume, для обычного перезапуска его использовать не нужно.

На Mac разработки Docker отсутствовал. Файлы контейнера подготовлены, но сборка linux/amd64 и запуск Compose здесь не проверены. Проверен Node standalone runtime, используемый контейнером. Ориентир десять минут из технички не заявляется измеренным Docker-результатом.

## Запуск на этом Mac без Docker

Нужен Node.js 22.14+ и npm. Зависимости и сборка уже подготовлены в рабочей папке.

```sh
npm ci
npm run build
npm start
```

`npm start` копирует локальные активы в standalone-сборку и запускает её на `0.0.0.0:8080`. JSON-хранилище остаётся в корневой `.data`, даже если Next меняет рабочую директорию runtime. Для разработки: `npm run dev`. E2E лучше выполнять на production-сборке, см. ниже.

Рекомендуемые ресурсы для демо: 2 CPU, 2 ГБ RAM; для сборки 4 ГБ RAM. Внешняя SQL-БД, Redis, платные ключи, загрузка моделей и голосовые инструменты для запуска приложения не нужны. Локальная среда `.tools/voice-env` использовалась только для расшифровки вложений и не входит в Git/Docker.

## Сеть и приглашения

На одном Mac открыть приглашение в другом браузере или инкогнито: это будут разные HttpOnly-сессии. Обычные вкладки одного браузерного профиля используют одну сессию.

Для телефона в той же Wi-Fi сети откройте `http://<IP-Mac>:8080`, создайте поездку и скопируйте ссылку из неё. `localhost` на телефоне обозначает сам телефон. Брандмауэр macOS и изоляция устройств сети могут блокировать доступ. Для внешнего доступа после самостоятельного деплоя задайте `APP_BASE_URL=https://ваш-домен` и `COOKIE_SECURE=true`.

Нельзя запускать несколько экземпляров с одним JSON volume: сериализация изменений действует внутри одного Node-процесса. Это временное хранилище для демо, не распределённая БД. Сохранённая сессия живёт 30 дней, восстановления по аккаунту в прототипе нет. Сохраняйте cookie браузера вместе с доступом к поездке.

## DeepSeek

После `cp .env.example .env` укажите в `.env`:

```dotenv
AGENT_PROVIDER=deepseek
DEEPSEEK_API_KEY=your_api_key_here
DEEPSEEK_MODEL=deepseek-flash
```

Ключ хранится только на сервере и исключён из Git и образа Docker. Для переключения работающего standalone-сервера перезапустите `npm start`; пересборка для смены ключа не нужна. Для проверки реального API: `node --env-file=.env --import tsx scripts/check-deepseek.ts`. Этот сценарий отправляет два синтетических сообщения, расходует небольшой объём токенов и сохраняет отчёт без ключа в `docs/verification-deepseek.json`.

Режим `AGENT_PROVIDER=mock` работает без сети и ключа. В режиме DeepSeek ошибки авторизации, баланса, таймаута и некорректный JSON показываются явно. Незаметного переключения на mock нет. `/health` сообщает выбранный тип агента, но не проверяет баланс и доступность внешнего API каждым запросом.

Модель получает личный диалог текущего участника и нормализованные общие пожелания. Чужие личные сообщения, токены приглашений, cookie и ключи в запрос не включаются. Ответ проверяется через Zod, после чего применяется обычной командой приложения. Сценарии и ранжирование остаются детерминированными, голосование и финальное подтверждение модель не меняет.

Документация API: [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), [JSON Output](https://api-docs.deepseek.com/guides/json_mode/). Проверено 27 октября 2026. Файлы исходных голосовых расшифровок и присланных референсов остаются локальными и не входят в публичную выгрузку.

## Данные и демо

Каталог уже находится в `src/data/fixtures/catalog.json`, фотографии и шрифт в `public/demo`. Первый запуск создаёт только необходимые JSON-файлы вне `public`, при перезапуске поездки не перезаписываются. Предгенерация `npx tsx scripts/seed.ts` воспроизводима, seed `271026`; это изменение каталога, не сброс личных поездок. Для старых локальных поездок предусмотрен одноразовый `npx tsx scripts/migrate-real-catalog.ts`: оригиналы сохраняются в `.data/before-real-catalog`, пожелания остаются, прошлые решения архивируются, выбор нужно пройти заново. Это исключает перенос голосов от вымышленных объектов к реальным.

- Сочи: 12 реальных отелей с официальными фотографиями, 18 мест, 8 переиспользуемых шаблонов сценариев.
- Петербург и Казань: по 3 реальных отеля с официальными фотографиями и 6 мест для ветки неизвестного направления. Они не равны проработке основного каталога.
- У каждого отеля 3 фотографии с его официального сайта. Привязки в `src/data/fixtures/real-hotels.json` и `public/demo/real/manifest.json`. Точная категория номера не подтверждена; если подходящего фото номера нет, показывается честное пустое состояние.
- Демо-цены за ночь за номер. Итог учитывает ночи и число номеров. Отель с неизвестной ценой требует уточнения и не становится финальным совпадением.
- Цены, параметры соответствия, время пешком и маршруты синтетические. Выдуманные отзывы и оценки реальным отелям не приписываются. Фотографии Сочи в обложках имеют отдельные источники в манифесте; они не делают фиктивные маршруты реальными.

На `/demo` каждое нажатие создаёт новую изолированную сцену. Это явный безопасный способ начать показ заново, не удаляющий собственные поездки. Сцены: одиночная, совместная с совпадениями, без общих сценариев, геоистория. Переключатель персон есть только в принадлежащих вам демо-сценах; он не заменяет реальные приглашения.

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/` | Начало и продолжение своих поездок |
| `/trips/new` | Состав, направление, длительность, номера |
| `/join/[token]` | Приглашение, личное вступление |
| `/trips/[id]/chat` | Личный диалог и редактирование пожеланий |
| `/trips/[id]/scenarios` | Выбор 1-3 сценариев и пересечение |
| `/trips/[id]/hotels` | Общая колода, голоса, пропуски, отмена |
| `/trips/[id]/hotels/[hotelId]` | Галерея, номер, план, схема, источники |
| `/trips/[id]/matches` | Совпадения, сравнение до 3, финальное подтверждение |
| `/trips/[id]` | Обзор, план и места, участники, материалы |
| `/host/demo` | Вопрос, свободный ответ, подтверждение evidence |
| `/trips/[id]/geo` | Подготовленная геоистория до/после |
| `/demo` | Готовые сцены |
| `/health` | JSON `{ "status": "ok", ... }`, HTTP 200 |

Промышленной авторизации и тестовых логинов нет. Имя вводится при создании/вступлении, сервер выдаёт непредсказуемую cookie. Каждый API-запрос к поездке проверяет членство. Нормализованные пожелания с автором общие, личные сообщения отдаёт только собственнику диалога. Просмотрщик, пришедший после финального выбора, не голосует, пока организатор явно не переоткроет подбор.

## Архитектура

```text
src/app                  маршруты UI и API
src/components/ui        Button, Input, Dialog, Chip, Avatar, Shell и состояния
src/features/trips       создание, контекст, пространство поездки
src/features/agent       диалог и редактируемый контекст
src/features/scenarios   самостоятельный этап сценариев
src/features/hotels      колода, жесты, галерея, схема маршрута
src/features/collaboration участники, приглашения, общий список
src/features/evidence    источники, конфликты, отельер, геоистория
src/domain               модели, единогласие, версии, финальные правила
src/application          команды, сессии, сценарии приложения
src/data/contracts       интерфейсы, Zod-команды, FeatureDefinition
src/data/adapters        fixture-каталог, JSON, mock/DeepSeek-агент, подбор, гео
src/data/fixtures        фиксированный каталог и словарь интересов
src/styles              токены и светлая тема, editorial-лендинг и колоды
public/demo              локальные активы, манифест и лицензия шрифта
docs                     ТЗ, техничка, архитектура, контракты, отчёт
```

Поток: UI -> application services -> отдельные CatalogRepository / TripRepository / AgentProvider / RecommendationProvider / GeoProvider. Компоненты не содержат каталога отелей и не обращаются к JSON-хранилищу.

В JSON-адаптере изменения сериализуются по поездке. Запись через временный файл и atomic rename. Поле `version` защищает от потерянных голосов, `commandId` предотвращает повтор одной мутации, клиент перечитывает состояние при 409. Отдельная `selectionRevision` относится к сценарию и голосам, предыдущие версии сохраняются в истории. Polling 2,5 секунды только в активной вкладке; после возврата перечитывание.

Подробнее: [архитектура](docs/architecture.md), [подключение данных](docs/data-integration.md), [HTTP-контракт](docs/api-contract.md), [отчёт проверок](docs/verification.md).

## Переменные

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `CATALOG_PROVIDER` | `fixture` | Подготовленный каталог |
| `TRIP_STORE` | `json` | Один Node-процесс, JSON вне public |
| `AGENT_PROVIDER` | `mock` | `mock` без сети или `deepseek` с настоящим API |
| `DEEPSEEK_API_KEY` | пусто | Секрет на сервере для режима deepseek |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Идентификатор модели DeepSeek |
| `RECOMMENDATION_PROVIDER` | `fixture` | Обязательные условия, затем мягкое ранжирование |
| `GEO_PROVIDER` | `fixture` | Подготовленные демонстрационные пути |
| `APP_BASE_URL` | пусто | Origin запроса для приглашения |
| `COOKIE_SECURE` | `false` | `true` при внешнем HTTPS |
| `TRIP_DATA_DIR` | `.data` | В контейнере `/app/data`, volume |

Выбор неподключённого провайдера приводит к понятной ошибке, не к тихому показу моков под видом API. Постоянная метка «Демо-данные» не отключается переменной.

## Дизайн и лицензии

Синий `#0E41D2` и бирюзовый `#32D6C5`, адаптация стиля Островка из ТЗ. Golos Text размещён локально под OFL, файл `public/demo/OFL.txt`. Лицензия не подразумевается для PT Root UI, его файлы не копировались. Иконки Phosphor, MIT. Motion и Radix используются для жестов и доступного модального примитива.

Реальные фотографии отелей: `public/demo/real/manifest.json`, источник каждого снимка и объект. Это публичные галереи официальных сайтов, открытая лицензия на повторную публикацию не заявляется. Перед публичным выпуском нужны права на фото или разрешённый каталог команды. Источники и ограничения записаны у каждого MediaAsset. Reveal адаптирован из Motion Primitives InView (MIT), лицензия в `docs/motion-primitives-LICENSE.txt`.

Фотографии: `public/demo/manifest.json` содержит source, license, assetId, object mapping и признак иллюстративности. Обложки Сочи: Alexey Elfimov, Sergey Beschastnykh и Mihail Tregubov, Unsplash License. Другие стоковые фото имеют исходный URL и ID снимка; имя автора, если оно недоступно, не выдумывается. Их использование не означает одобрение продукта авторами. `scripts/download-assets.py` скачивает только отсутствующие активы по сохранённому манифесту; для запуска приложения он не нужен. Присланные референсы находятся в docs/references и не используются как фотографии отелей.

## Что остаётся к финальной сдаче

1. Подключить каталог и агент команды через согласованные адаптеры. Демо не выполняет настоящее автономное исследование источников.
2. Реально вычислить хотя бы одну характеристику по геоданным и проверить качество. FixtureGeoProvider и переключатель до/после не закрывают это требование трека.
3. Проверить Docker/Compose на машине с Docker, включая `linux/amd64` и сохранность volume.
4. Перенести код в выданный команде репозиторий, записать и опубликовать скринкаст. Добавить ссылку сюда и проверить без входа.
5. В дедлайн по отдельной команде пользователя поставить `submission` на финальный коммит основной ветки.
