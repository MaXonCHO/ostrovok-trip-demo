# Островок — локальный прототип

Репозиторий: [MaXonCHO/ostrovok-trip-demo](https://github.com/MaXonCHO/ostrovok-trip-demo).

Адаптивный сайт в стиле Островка: главная, поиск, страницы отелей и избранное. Next.js, React и TypeScript. Каталог и изображения локальные. Для диалога нужен серверный ключ DeepSeek; каталог работает и без него.

Подробная передача контекста для следующего чата Codex: [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md).

## Запуск

```sh
npm ci
npm run dev
```

Сайт с обновлением при изменении файлов: [localhost:8080](http://localhost:8080).

Для production-сборки:

```sh
npm run build
npm start
```

Docker: `docker compose up --build`. Чтобы передать ключ: `docker compose --env-file .env.local up --build`. Проверка доступности: `/health`.

## Диалог и подбор

Создайте `.env.local` рядом с `package.json` (образец — `.env.example`):

```env
DEEPSEEK_API_KEY=ваш_ключ
DEEPSEEK_MODEL=deepseek-flash
```

Ключ используется только сервером, исключён из Git и Docker-образа. Не добавляйте к имени переменной префикс `NEXT_PUBLIC_`. В dev Next перечитывает файл при сохранении; после изменения ключа в production перезапустите сервер.

- `/` — первый экран, ввод текстом или голосом и встроенные фильтры. Общие заголовки и кнопка сохраняют положение при переключении.
- `/my-trip` — продолжение запроса в диалоге с DeepSeek. Сначала уточняются город, даты, бюджет и участники; затем можно выбрать несколько карточек типов отдыха и перейти к деталям. Уже сообщённые параметры не запрашиваются заново.
- `/search` — локальный каталог с фильтрами, сортировкой и избранным. В демо направление по умолчанию — Санкт-Петербург, в диалоге доступны три его отеля. Исходные 18 объектов сохранены в данных.
- `/hotel/helvetia-saint-petersburg` — пример страницы петербургского отеля с галереей и демонстрационными тарифами.
- `/favorites` — избранное текущего браузера.

Переписка хранится в localStorage браузера и восстанавливается при возвращении в «Мою поездку». При уходе со страницы незавершённый запрос отменяется. Голосовой ввод включается только по кнопке через SpeechRecognition браузера; при отсутствии поддержки остаётся текстовый ввод.

Ответы ИИ появляются постепенно; при уменьшении движения в настройках системы сразу показывается полный текст. Текст сообщений не интерпретируется как HTML. При ошибке сервиса доступен повтор без дублирования вопроса; скрытой подмены DeepSeek локальным mock-агентом нет.

После подтверждения города появляется фотография Петербурга, предоставленная пользователем. Погодный значок слева показывает данные на подтверждённые даты; пояснение открывается при наведении, фокусе или нажатии. Ближайшие даты используют прогноз, прошлые — архив, отдалённые будущие — явно подписанный исторический сезонный ориентир, а не точный прогноз. Источник: [Open-Meteo](https://open-meteo.com/en/docs), [архив](https://open-meteo.com/en/docs/historical-weather-api).

Под диалогом — белая шторка с тематическими подборками и каруселями отелей. Первые варианты видны сразу из локального каталога. Затем темы и допустимый пул отелей выбирает DeepSeek с учётом истории; при уточнении они сужаются. Выбор карточек типов отдыха не скрывает подборки отелей. Идеи взяты из [О!Блога: Петербург на выходные](https://blog.ostrovok.ru/peterburg-na-vykhodnye/) и других статей, ссылки и происхождение фотографий указаны в `public/ostrovok/collections/sources.json`. Это редакционные темы, а не подтверждение особых свойств каждого отеля.

Используется [Chat Completions API DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/), JSON-ответы проверяются на сервере. Модель по умолчанию — `deepseek-flash`. `POST /api/trip-chat` ограничивает размер истории, время ожидания и допустимые ID отелей/подборок. При пустом или некорректном ответе DeepSeek выполняется один повтор с принудительной структурированной функцией; её аргументы используются только как данные и проходят ту же проверку. Обе попытки ограничены общим таймаутом 25 секунд. `GET /api/trip-weather` запрашивает погоду без API-ключа и кэширует ответы.

Цены, удобства и тарифы демонстрационные. Оплата и бронирование не подключены. Футер повторяет текущий публичный [Островок](https://ostrovok.ru); оригинальные активы и источники — `public/ostrovok/footer/sources.json`.

## Файлы проекта

- `src/features/ostrovok/` — текущие компоненты, каталог и логика поиска.
- `src/app/` — страницы и общая оболочка сайта.
- `src/styles/` — стили, локальные шрифты PT Root UI и Spoof.
- `src/data/fixtures/real-hotels.json` — названия, адреса, источники и фотографии отелей для текущего каталога.
- `src/data/fixtures/catalog.json` — дополнительные исходные данные тех же 18 отелей, сохранённые для дальнейшей работы.
- `public/demo/`, `public/ostrovok/` — фотографии, иллюстрации, шрифты и сведения об источниках.
- `Брендбук Островка/`, `HACKATHON_CONTEXT.md` — брендбук и контекст задачи.
- `docs/` — исходные материалы задачи, аудит типографики и проверка текущего интерфейса.

Прежний прототип совместных поездок, агентный сервер, голосования и кабинет отельера удалены. Фотографии и все записи отелей сохранены.
