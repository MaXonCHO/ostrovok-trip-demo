# Статьи о Петербурге — подборка из блога Островка

Отдельная самостоятельная папка с кодом сборщика и отобранными материалами.
В подборке 25 статей разных тем: необычные места, гастрономия, маршруты,
природа, выбор жилья, практические советы, семейный и сезонный досуг.

Сбор выполнен 28 октября 2026 года: **25 карточек и 129 изображений**.
Даты публикаций — с 12 марта 2020 года по 28 октября 2026 года.
Каждая карточка имеет дату и хотя бы одно изображение.

Для каждого материала сохраняются заголовок, автор, дата публикации, ссылка
на оригинал, самостоятельно написанное краткое описание, тема и фотографии.
Это каталог кратких карточек с иллюстрациями и ссылками; полные тексты сторонних
статей в папку не копируются.

## Разбор структуры текста (дополнение 28 октября 2026)

`blog_parser/body.py` добавляет `extract_body(html, url)` для разбора основного
тела `article.post-single .post-text`. Он сохраняет порядок заголовков, абзацев,
списков и изображений, исключает рекламу, навигацию, скрытые элементы, подписку
и блоки соседних материалов. Результат — данные, а не исполняемый HTML.
Существующий сборщик карточек, `articles/*/article.json` и `data/articles.json`
не меняются; полные тексты в собранном наборе по-прежнему отсутствуют.

Для проверки публичных страниц **без сохранения или вывода текста**:

```bash
python3 article_text.py inspect --selection data/selection.json --limit 3
python3 article_text.py inspect --url https://blog.ostrovok.ru/luchshie-kofejni-peterburga/
```

Команда выводит URL, число блоков каждого типа и число текстовых символов.
HTML и тело статьи существуют только в памяти на время проверки. Для обработки
собственного или предоставленного HTML используется отдельный локальный режим:

```bash
python3 article_text.py extract --html /path/to/local-article.html \
  --url https://blog.ostrovok.ru/local-fixture/ --output /tmp/article-body.json
```

Локальный экспорт требует явно переданного HTML и нового отдельного файла;
существующие файлы, `articles/` и `data/` не перезаписываются. Базовый URL нужен
для разрешения относительных ссылок на фотографии. Схема результата:

```json
{
  "schema_version": 1,
  "source_url": "https://blog.ostrovok.ru/local-fixture/",
  "blocks": [
    {"type": "heading", "level": 2, "text": "Учебный раздел"},
    {"type": "paragraph", "text": "Локальный учебный абзац."},
    {"type": "list", "ordered": false, "items": ["Первый пункт", "Второй пункт"]},
    {"type": "image", "url": "https://blog.ostrovok.ru/wp-content/uploads/example.webp", "alt": "Учебный вид", "caption": "", "credit": ""},
    {"type": "quote", "text": "Локальная учебная цитата."},
    {"type": "table", "rows": [["Колонка", "Значение"], ["Пример", "1"]]}
  ]
}
```

Вложенные списки представлены один раз внутри текста родительского пункта.
Подпись и автор фотографии находятся в блоке изображения и не дублируются
отдельным абзацем. URL изображений проходят проверку формата HTTPS; скрипты,
iframe и исходная HTML-разметка в результат не входят. Для отображения следует
создавать элементы из типов блоков и выводить строки как текст, без innerHTML.

Проверки: `python3 -m unittest discover -s tests -v` — 20 тестов, включая
порядок блоков, исключение рекламы, картинки внутри абзаца, вложенные списки,
таблицы, подписи и локальный CLI. Тестовые HTML и тексты синтетические.

## Открыть подборку

Перейдите в папку из Терминала:

```bash
cd "/Users/lovelnpvlv/Desktop/Проекты/Парсер хакатон островок/ostrovok_blog_parser"
open index.html
```

Для просмотра уже собранных данных Python и интернет не нужны. На главной
странице есть поиск, фильтры по темам и даты. Карточка материала ведёт на
локальную фотогалерею и на исходную статью.

Если хотите открыть подборку через локальный веб-сервер:

```bash
python3 -m http.server 8766 --bind 127.0.0.1
```

Затем откройте `http://127.0.0.1:8766/`. Остановить сервер можно через `Ctrl+C`.

## Как выбирались материалы

Отправная точка — [указанный поиск по Санкт-Петербургу](https://blog.ostrovok.ru/?s=%D0%A1%D0%B0%D0%BD%D0%BA%D1%82-%D0%9F%D0%B5%D1%82%D0%B5%D1%80%D0%B1%D1%83%D1%80%D0%B3).
Дополнительно проверены варианты «Петербург» и «Питер» на том же блоге:
названия многих полезных материалов не содержат полную форму названия города.
Исходный URL поисковой выдачи сохранён в `discovered_from`.

После поиска отобраны именно материалы о городе и окрестностях. Подборка
сочетает известные достопримечательности с нишевыми местами, едой, бесплатным
досугом, экотропами, семейными занятиями и идеями проживания. Случайные материалы
о других городах и старые новости про ограничения в подборку не включались.

Среди тем — небольшие музеи, культурные пространства, промышленный туризм,
смотровые площадки, авторские рестораны, локальные кофейни, блюда Петербурга,
пригородные дворцы, глэмпинги, районы и сувениры.

## Даты и фотографии

- `date_published` — дата из `time[itemprop=datePublished]` внутри основной
  статьи. Если атрибута нет, проверяется элемент `time` той же статьи.
- `date_published_raw` — исходное значение даты со временем и часовым поясом,
  когда сайт их указал.
- `date_source` — место, откуда извлечена дата. Дата соседних рекомендаций,
  поисковой карточки или дата скачивания не подменяют публикацию.
- `date_modified` — дата обновления из явной метки сайта, если она найдена;
  иначе `null`. Год в заголовке не используется вместо даты.
- `collected_at` — отдельное время сбора в UTC.

Возраст материала сам по себе не означает его бесполезность: в подборке есть
исторические гиды. Цены, программы, расписания и доступность мест из оригинала
относятся к дате статьи и могут измениться.

По умолчанию сохраняется до 6 уникальных фотографий на материал: обложка и
иллюстрации разных разделов. У короткой новости может быть только одна
фотография. Рекламные блоки, аватары и рекомендации других статей исключаются.
Файлы проверяются как изображения и преобразуются в WebP, длинная сторона —
не более 1600 пикселей. Хэши помогают исключать повторные изображения внутри
одной статьи.

В метаданных каждой фотографии сохранены `original_url`, `source_url`, размер,
SHA-256, роль обложки/иллюстрации и `credit`, если автор указан рядом со снимком.
Подпись обозначает раздел исходной статьи, а не результат визуального
распознавания изображения. Длинные исходные подписи не копируются.
`rights_status: unknown` означает, что сборщик не устанавливает право
дальнейшего размещения фотографии на другом сайте.

## Установить зависимости для повторного сбора

Нужен Python 3.10 или новее. Из папки `ostrovok_blog_parser`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Единственная дополнительная библиотека — Pillow. При следующем запуске
окружение активируется командой `source .venv/bin/activate`.

## Повторить сбор выбранных материалов

```bash
python collect_articles.py run --max-photos 6 --resume
```

`--resume` пропускает статьи с уже сохранёнными данными при неизменном выборе
и лимите фотографий. Пропавший локальный файл вызывает повторный сбор.
Если часть снимков не загрузилась и лимит не достигнут, статья пробуется снова.
Ошибка одной статьи не мешает остальным; сведения сохраняются после каждого
завершённого материала. Остановить работу можно через `Ctrl+C`.

Повысить лимит фотографий:

```bash
python collect_articles.py run --max-photos 10 --resume
```

Пересобрать страницы и общий JSON из сохранённых данных без сети:

```bash
python collect_articles.py export
```

## Изменить подборку

Найти дополнительные кандидаты:

```bash
python discover.py --query "Петербург" --pages 4
```

В `data/candidates.json` появятся ссылки и метаданные поисковых карточек.
Выбор для финального сбора задаётся отдельно в `data/selection.json`:

```json
{
  "url": "https://blog.ostrovok.ru/peterburg-na-vykhodnye/",
  "category": "unusual",
  "summary": "Краткое самостоятельно написанное описание материала.",
  "tags": ["необычные места", "выходные"]
}
```

Поддерживаемые категории: `unusual`, `food`, `routes`, `nature`, `housing`,
`tips`, `family`, `seasonal`. После изменения выбора повторите `run`.
Сборщик не сохраняет полные тексты статей и исходные HTML-страницы.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют извлечение даты именно из основной статьи, исключение рекламы
и чужих изображений, валидацию фотографий, отсутствие полного текста в
результате, формирование фотогалерей и корректность входных URL.

Все 12 тестов прошли. Дополнительно проверены SHA-256 и открытие всех 129
файлов изображений, локальные ссылки в 26 HTML-страницах, 9 кнопок фильтров
и поиск по темам. Обложки всех 25 материалов просмотрены на обзорном листе.

Запросы идут с паузой. При 429 или 403 на странице статьи сборщик прекращает
обращения к этому хосту до следующего запуска. При 403 на отдельном файле
изображения запрещённый URL больше не запрашивается; остальные публичные
страницы и изображения могут обрабатываться. TLS-проверка остаётся включённой; капчи и блокировки
не обходятся. Подробности проблем отдельного снимка находятся в `errors`
соответствующего `article.json`.
