# Хакатон «Островок» — контекст трека

Трек: **«О!дин шаг до идеального отеля»**. Найти отель под индивидуальные пожелания, даже если нужных характеристик нет в карточке.

Источник: [условия трека](https://docs.ostrovok.tech/s/25890594-997e-45c1-9649-63c388088231), прочитаны из предоставленной HTML-копии 27 октября 2026 года.

## Задача и ценность

Создать работающий прототип агентной системы, которая собирает необычные характеристики отелей и номеров из открытых данных и ответов отельеров, хранит их и подбирает отели по запросу на естественном языке.

Путешественнику — меньше ручного поиска и разочарований; Островку — более точный подбор, рост конверсии и меньше отмен; отельеру — возможность показать сильные стороны и отвечать на повторяющиеся вопросы один раз.

## Обязательные задачи

- **Сбор:** агент выбирает источники и инструменты для характеристики и получает значение. Минимум одна характеристика **вычисляется по геоданным**, а не извлекается из текста.
- **Диалог с отельером:** при нехватке данных агент формулирует вопрос и преобразует свободный ответ в структурированные поля. Отельера разрешено имитировать.
- **Достоверность:** у каждого значения есть источник, уверенность и дата получения; система обнаруживает и разбирает противоречия между источниками.
- **Расширяемость:** новую характеристику можно добавить без переписывания системы, например текстовым описанием.
- **Поиск:** запрос своими словами, например «тихий номер с видом на закат недалеко от моря», возвращает подходящие отели.

## Рамки и результат

- API, MCP-серверы и данные Островка **не предоставляются**. Список отелей, данные, инструменты агентов, логика и интерфейс собираются самостоятельно.
- Технологии, модели и архитектура — на выбор команды.
- Прототип должен работать на наборе отелей выбранного региона; организаторы рекомендуют глубоко проработать **один регион**.
- Запуск по README без многочасового сбора данных: заранее подготовленные демо-данные должны лежать в репозитории.
- Если нужен ключ LLM — описать настройку в README и приложить `.env.example`.
- Ключевой акцент — доказуемость: откуда получено значение, насколько оно надёжно, как проверяется и когда устареет. Догадка LLM без данных не считается решением.

## Идеи и источники — необязательные примеры

- Вид на закат, море, горы или достопримечательности: DEM (SRTM/Copernicus), здания OSM, прямая видимость с учётом этажа, фасада и дат.
- Тишина: дороги, железная дорога, бары, аэропорты, открытые карты шума.
- Пешая доступность, ночная инфраструктура, детские площадки, парковки и зарядки: OSM, реальные маршруты, рельеф, `opening_hours`.
- Транспорт из аэропорта: GTFS; климат: Open-Meteo; воздух: OpenAQ; сотовая связь: OpenCellID.
- Стройки и события: городские открытые данные; история здания: Wikidata/Википедия; фотографии: Wikimedia Commons/Mapillary.
- Уточнения у отельера: сторона окон, шумоизоляция, правила проживания с питомцами и стоимость.

## Дополнительные задачи

Объяснение соответствия запросу и ограничений; сравнение отелей/номеров; кабинет отельера с подтверждением и исправлением данных; актуализация устаревших значений; размеченная выборка и метрики точности, покрытия и доли вопросов к отельеру.
